# Smart Irrigation System – Firebase Data Model

## Overview

This document defines the Firebase Realtime Database structure used for the Smart Irrigation System. The design is optimized for IoT constraints such as low bandwidth, minimal payload size, and efficient processing on embedded devices (ESP-IDF).

The structure supports multiple zones and gateways while maintaining simplicity and scalability.

---

## Design Principles

* Minimal data size using short keys
* Flat structure for fast parsing and low memory usage
* Separation of sensor data and control commands
* Scalable using dynamic IDs for zones and gateways
* Optimized for periodic polling communication

---

## Top-Level Structure

```
system/
gateways/
zones/
commands/
weather/
```

---

## Node Descriptions

### 1. system

Stores global system state.

* `mode`: operation mode (`auto` or `manual`)

---

### 2. gateways/{gatewayId}

Represents each gateway device.

* `pump`: pump state (true/false)
* `waterLevel`: water tank level
* `lastSeen`: last heartbeat timestamp

---

### 3. zones/{zoneId}

Represents each irrigation zone.

* `g`: gateway ID
* `sm`: soil moisture
* `t`: temperature
* `f`: flow rate
* `v`: valve status (true/false)
* `lu`: last update timestamp
* `th`: moisture threshold
* `dur`: irrigation duration (seconds)

Each zone contains both sensor readings and configuration parameters.

---

### 4. commands/{gatewayId}

Commands generated by the cloud and consumed by the gateway.

* `pump`: desired pump state
* `z/{zoneId}/v`: valve command (true/false)
* `z/{zoneId}/d`: irrigation duration (seconds)
* `ts`: last command update timestamp

The gateway periodically polls this node and executes commands.

---

### 5. weather

Stores external weather data used in irrigation decisions.

* `rain`: rain expected (true/false)
* `temp`: current temperature
* `ts`: last update timestamp

---

## Data Flow

1. Zones send sensor data to the gateway
2. Gateway uploads data to `zones/` and `gateways/`
3. Cloud logic evaluates conditions
4. Commands are written to `commands/`
5. Gateway polls commands and controls pump/valves

---

## Notes

* All timestamps use Unix time
* Keys are intentionally shortened to reduce network usage
* The structure is designed for real-time updates and low-latency control
* Additional features (logs, analytics) can be added without affecting core operation
